# Как получить почти «бесплатную безлимитную» AI-среду с модификациями из GitHub

Коротко: настоящего бесплатного облачного безлимита не существует. Если сервис бесплатный, у него есть лимиты по времени, GPU, очереди, скорости, размеру модели или правилам использования. Самый честный путь без API-лимитов — **локальный запуск open-source модели** на своём ПК/сервере + веб-интерфейс + плагины/моды.

## 1. Что значит «безлимитно» на практике

Можно убрать платные API-лимиты, если модель работает у тебя:

- нет оплаты за каждый запрос;
- можно подключать свои плагины и код;
- можно хранить свои данные локально;
- Android не обязан тянуть модель — телефон может быть только экраном.

Но остаются физические лимиты:

- RAM/VRAM;
- скорость CPU/GPU;
- место на диске;
- электричество;
- качество маленьких моделей ниже, чем у больших.

## 2. Рекомендованная архитектура

```text
Android / браузер
        ↓
Open WebUI на ПК или VPS
        ↓
Ollama
        ↓
open-source модель: Llama, Mistral, Gemma, Phi и т.п.
        ↓
плагины / tools / GitHub-модификации
```

В этом репозитории уже есть `docker-compose.yml`, который запускает Ollama + Open WebUI.

## 3. Запуск

```bash
docker compose up -d
```

Открыть:

```text
http://localhost:3000
```

Скачать маленькую модель:

```bash
./scripts/pull-model.sh llama3.2:1b
```

Или модель побольше:

```bash
./scripts/pull-model.sh llama3.2:3b
```

Если модель не находится в каталоге Ollama, выбери актуальную модель из библиотеки Ollama и передай её имя в скрипт.

## 4. Какие модели выбирать

С учётом твоего предпочтения в этом kit по умолчанию не рекомендуются Qwen и DeepSeek. Начальные варианты без них: `llama3.2:1b`, `llama3.2:3b`, `gemma2:2b`, `phi3:mini`, `mistral:7b` — выбирай по мощности железа.

Ориентиры, не железное правило:

| Железо | Что пробовать |
|---|---|
| слабый ПК / ноутбук / Android | 0.5B–1.5B quantized |
| 8 GB RAM | 1.5B–3B quantized |
| 16 GB RAM | 3B–8B quantized |
| NVIDIA GPU 8–12 GB VRAM | 7B–8B Q4/Q5 |
| мощный ПК / сервер | 14B+ quantized |

Если всё лагает — модель слишком большая. Уменьшай размер модели, контекст и число параллельных запросов.

## 5. Где искать не промпты, а плагины/код

Ищи не «super prompt», а проекты с реальной интеграцией:

### Ключевые слова для поиска

```text
ollama open webui tools github
open-source ai agent framework ollama plugins
local llm function calling github
openai compatible local llm tools
continue dev ollama vscode
flowise ollama local tools
dify ollama local deployment
llama.cpp android gguf termux
```

### На что смотреть в репозитории

- есть ли `Dockerfile` или `docker-compose.yml`;
- есть ли поддержка Ollama или OpenAI-compatible API;
- есть ли папки `tools`, `plugins`, `extensions`, `functions`;
- есть ли README с установкой;
- жива ли разработка: свежие коммиты, issues, releases;
- какая лицензия;
- не требует ли проект платный API как единственный вариант.

## 6. Полезные классы инструментов

### Веб-интерфейс

- Open WebUI — удобный интерфейс к Ollama, поддерживает локальные модели и расширения.
- AnythingLLM — рабочие пространства, документы, локальные/удалённые модели.

### No-code / low-code агенты

- Flowise — визуальная сборка цепочек и агентов.
- Dify — приложения, workflows, RAG, API.
- n8n — автоматизация действий и интеграций.

### IDE / кодинг

- Continue — расширение для VS Code/JetBrains, можно подключать Ollama.
- Aider-подобные CLI-инструменты — удобно для правок кода, но проверяй требования к API.

### Низкоуровневый запуск моделей

- Ollama — проще всего для старта.
- llama.cpp — гибко, GGUF-модели, можно запускать на разном железе.
- vLLM / text-generation-inference — чаще для серверов и GPU.

## 7. Как добавлять модификации из GitHub

Вариант через скрипт:

```bash
./scripts/clone-mod.sh https://github.com/user/repo.git
```

Вариант через локального агента:

```bash
python3 local_agent.py
```

Потом внутри агента:

```text
/github_clone https://github.com/user/repo.git
/readme mods/repo
```

Дальше не запускай код вслепую. Сначала:

1. прочитай README;
2. проверь `requirements.txt`, `package.json`, `Dockerfile`;
3. посмотри issues;
4. запускай в Docker или виртуальном окружении;
5. не давай токены и пароли непроверенному коду.

## 8. Чем плагин отличается от промпта

Промпт — это инструкция модели:

```text
Отвечай как программист и помогай с Android.
```

Плагин — это код, который реально что-то делает:

- клонирует репозиторий;
- читает файл;
- вызывает API;
- запускает тесты;
- работает с базой данных;
- создаёт документы.

Лучше использовать оба слоя:

```text
Промпт задаёт поведение → плагин выполняет действие → модель объясняет результат.
```

## 9. Android без лагов

Лучший вариант:

1. модель работает на ПК, ноутбуке или VPS;
2. Open WebUI открыт на этом устройстве;
3. Android подключается через браузер;
4. телефон не выполняет инференс, поэтому не перегревается и не тормозит.

Если ПК и телефон в одной сети:

```bash
hostname -I
```

Потом открыть на телефоне:

```text
http://IP_ПК:3000
```

Если подключаешься извне, безопаснее использовать VPN вроде Tailscale/ZeroTier. Не выставляй Open WebUI в интернет без пароля, HTTPS и понимания рисков.

## 10. Если нужен именно телефон без ПК

Можно пробовать маленькие GGUF-модели через Android-приложения или Termux + llama.cpp, но ждать «без лагов» не стоит. Для слабого Android выбирай очень маленькие модели 0.5B–1.5B и короткий контекст.

## 11. Практичный план

1. Поставь Docker на ПК.
2. Запусти `docker compose up -d`.
3. Скачай маленькую модель через `./scripts/pull-model.sh llama3.2:1b`.
4. Открой Open WebUI.
5. Подключи Android к `http://IP_ПК:3000`.
6. Для кода используй `local_agent.py` и папку `plugins/`.
7. Моды из GitHub складывай в `mods/` и запускай только после проверки.

Так ты получишь не магический «промпт», а реальную основу: локальная модель + веб-интерфейс + плагины + код из GitHub.
